# Custom Skills and Always-Apply Rules

This guide explains how to add your own skills and always-apply rules for
Cursor, Claude Code, and OpenCode, and how reinstalls treat your changes.

---

## How skills work

A skill is a folder containing a `SKILL.md` file with YAML frontmatter. The tool
reads the frontmatter `name` and `description` fields to offer the skill to the
agent.

```
<skill-name>/
  SKILL.md          # required — frontmatter + body
```

The frontmatter must be at the very top of the file, fenced with `---`:

```yaml
---
name: my-skill
description: One-line summary of what this skill does and when to invoke it.
---
```

The body below the closing `---` is the skill's actual prompt content — instructions,
steps, examples, or whatever the agent should follow when the skill is active.

See `cursor-extras/skills/add-memory/SKILL.md` for a real example of correct
frontmatter and body structure.

---

## Where to place skills

There are two locations, depending on whether you want a skill to travel with
the repo or stay local to your machine.

### Repo-shipped skills (shared with the team)

Drop the skill folder under `cursor-extras/skills/`:

```
cursor-extras/skills/<name>/SKILL.md
```

`install.sh` installs every folder under `cursor-extras/skills/` into each wired
tool's skills folder. The memory system's built-in skills (`add-memory`,
`query-memory`, `capture-notes-to-memory`, and others) live here. The folder
keeps its historical name; its skills are shared by all three tools.

| Tool | Skills folder |
|---|---|
| Cursor | `~/.cursor/skills/<name>/SKILL.md` |
| Claude Code | `~/.claude/skills/<name>/SKILL.md` |
| OpenCode | `~/.config/opencode/skills/<name>/SKILL.md` (or under `$XDG_CONFIG_HOME/opencode/`) |

The shipped skills run the CLI through
`python3 "${SILLY_MEMORY_HOME:-$HOME/.silly-memory}/bin/memory"`,
so they reach the installed engine wherever its home is.

### Local-only skills (your machine only)

Drop the skill folder directly into a tool's skills folder from the table above,
for example:

```
~/.claude/skills/<name>/SKILL.md
```

A skill whose name is not one of the shipped ones is never touched by
`install.sh` or `uninstall.sh` and never appears in the repo.

## SKILL.md skeleton

Copy this template into your new skill folder and fill in the blanks:

```markdown
---
name: your-skill-name
description: When to invoke this skill and what it accomplishes (one sentence).
---

# Your Skill Title

## When to use
- Describe the trigger condition or user intent.

## Instructions
1. Step one.
2. Step two.
3. Step three.
```

Keep the `name` field lowercase and hyphenated. The `description` is what the
tool uses to pick the skill, so make it specific enough to distinguish this skill
from others.

## Always-apply rules

If you want a prompt to apply automatically to every conversation rather than
on demand, use a rule instead of a skill.

- **Cursor:** a `.mdc` file in `~/.cursor/rules/` with `alwaysApply: true` in its
  frontmatter:

  ```markdown
  ---
  alwaysApply: true
  ---

  Your prompt content here.
  ```

- **Claude Code:** a plain Markdown file in `~/.claude/rules/`.
- **OpenCode:** there is no rule folder the memory system uses. The silly-memory
  plugin adds its recall rule to each session itself.

The memory system's deep-recall rule follows this pattern: `install.sh` installs
`~/.cursor/rules/memory-recall.mdc` for Cursor and
`~/.claude/rules/memory-recall.md` for Claude Code, and keeps an engine copy at
`~/.silly-memory/cursor-extras/rules/memory-recall.mdc` for the OpenCode plugin.

Project rules generated by the memory system (`.cursor/rules/_memory-context.mdc`
and `.claude/rules/_memory-context.md`) are rewritten on every refresh; do not
edit them by hand.

---

## Reinstall and uninstall behavior

`install.sh` records every rule and skill file it writes, with its digest, in
`~/.silly-memory/.installed-artifacts.json`. On a rerun, for each shipped file:

- **Missing:** it is installed.
- **Unchanged since the last install:** it is replaced with the current version.
- **Changed by you, or not a silly-memory file at all** (a same-named file of
  your own): it is left alone, and the installer prints a warning naming it.

`uninstall.sh` removes a rule or skill only if it still matches what was
installed; anything you changed stays.

To pick up the shipped version of a skill you customized, delete your copy and
rerun `./install.sh`.
